# WI-011 Reporting Read Model Plan

## Implementation sequence

1. Bind the read-only Reporting boundary, section rules, no-goals, authorization, and current-WI issue policy in the Contract.
2. Add failing tests for card fact retention, Top5 capacity, section order, duplicate identity, and packet grouping.
3. Implement pure card, section, Top5, packet, and assembly types.
4. Run focused tests, architecture checks, formatting, lint, and the full repository suite.
5. Record Summary and Outcome evidence, archive the WI, then publish and merge its PR.

## Scope guard

Reporting does not recompute Stage, Ranking, Threshold Distance, evidence
quality, or section membership. Rendering, persistence, scheduling, and
delivery remain later boundaries. In-scope problems are fixed here rather than
creating a new WI.

## Verification commands

Use the commands listed in the design spec and Contract. A successful result
must show that one packet preserves the same supplied cards and four sections.
